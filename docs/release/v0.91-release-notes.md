# Cala's Pokecom BASIC v0.91 リリースノート

## 概要

v0.91 は、通信経路とメモリアーキテクチャを重点的に見直したリリースです。USB CDC / UART file transferのbulk化、PicoCalc PSRAMのmulti-client利用、INTERNAL Program Storageの1,024行×2,047文字化、DirectStateとCompiled Program cache、Control Center再編、長大programの操作改善をまとめています。

v0.90からのBASIC言語互換性を維持しながら、待機時SRAM使用量を大きく削減し、PSRAMを「保存・cache層」、内部SRAMを「実行working set」とする構成へ整理しました。

## Stage 1 - Serial Performance / Control Center

- USB CDC bulk read
- YMODEM RX header / payload / CRCのbulk exact-read
- YMODEM TX packet coalesce
- UART RX 4096-byte ring buffer
- UART baud 115200 / 230400 / 460800 / 921600
- optional RP2350 RX-only DMA
- transfer cancel polling 25 ms
- Bluetooth SPP/RFCOMMを復活させず、現行のUSB CDC / UART0 transportを維持
- Control Centerをカテゴリ階層へ再編し、menu labelの`...`を廃止

921600 bps・YMODEM DMAの実機測定:

| Direction | 実測 |
|---|---:|
| PC -> PicoCalc | 約33 KB/s |
| PicoCalc -> PC | 約62 KB/s |

IRQとDMAのthroughput差は小さく、DMAは主としてRX CPU負荷低減のために使用します。

## Stage 2 - PSRAM / SRAM Architecture

- PSRAM allocatorをmulti-client化
- Editor History / Program Store / SD Cache / Direct State / Compiled Cache / Audio Cacheのclient区分
- INTERNAL ProgramStoreをPSRAM優先へ移行
- SD-backed ProgramStoreへ64 KiB read-only PSRAM cache
- VMのnumeric/string array poolを常駐SRAMから外し、DIM使用時だけlazy allocation
- PSRAM diagnosticsとruntime client ownershipを整理
- System Informationにclient allocationとcache hit/missを追加

Stage 2時点でStatic SRAMはv0.90比77,692 bytes削減されました。

## Stage 3 - Runtime Memory / Compile Cache

- DirectState約9.7 KiBをVM常駐領域から分離
- Direct statement開始時にPSRAM/SRAM snapshotから内部SRAMへ復元し、終了時に保存
- persistent `CompiledProgram` 約33.9 KiBをReplから削除
- RUN / direct実行時だけ内部SRAMへCompiledProgram workspaceを確保
- stored-program RUN用PSRAM compiled cache
- cache header + CRC32検証
- ProgramStore revisionによるstale cache排除
- extended line mapを含むcompiled program復元
- VMはPSRAM上のopcodeを直接実行せず、内部SRAM working setから実行

## Enhanced INTERNAL Program Storage

PSRAM利用時のINTERNAL RAMをSD CARDと同じsource容量へ拡張しました。

| backend | 最大行数 | 1行本文 |
|---|---:|---:|
| INTERNAL / PSRAM | 1,024 | 2,047 |
| INTERNAL / SRAM fallback | 256 | 191 |
| SD CARD | 1,024 | 2,047 |

INTERNAL PSRAMはcompact indexと固定2 KiB text slotを使用し、行挿入・削除時に約2 MiBの本文領域全体をshiftしません。

SD上の1,024行programを内容を保持したままINTERNAL PSRAMへ切り替えられます。

## 操作改善

- `LIST`をBREAK / Esc / Ctrl-Cで途中停止可能
- 2,047文字lineのLIST中もbounded chunk単位でBREAKを確認
- LOAD開始時に`LOADING... (filename)`
- RUN開始時に`RUN...`
- Control Centerをrow 37まで拡張
- row 38を空行、row 39をFunction Key barとして維持
- 大規模INTERNAL programもFull-Screen Editorで編集可能

## 実機検証

1,024行stress program `CPB_LIMIT_1024.BAS` を使用し、次を確認しました。

```text
Program Storage = SD
LOAD "CPB_LIMIT_1024"
Program Storage = INTERNAL RAM
RUN
RUN
LIST
BREAK / Ctrl-C
```

実機出力:

```text
IL STRESS PASS
FAR-LINE GOSUB PASS @10100
FAR CHECK=9902
RETURNED FROM FAR-LINE SUBROUTINE
```

確認範囲:

- 1,024行source
- 2,047文字source line
- numeric array 4,096 cells
- string array 512 cells
- 325-line IL stress
- extended line map / far GOSUB
- SD -> INTERNAL PSRAM migration
- repeated RUN
- large-file editing
- LIST interruption
- Control Center layout

## Compatibility / Installation

- 対象hardwareはClockworkPi PicoCalc + Raspberry Pi Pico 2 Wです。
- v0.90のBASIC sourceとの互換性を維持します。
- Direct mode / `BASIC>` interactive inputは191文字のままです。
- BluetoothはClassic HID / BLE HID Keyboard用途です。Classic SPP file transferは現行機能ではありません。
- `flash-cpb.cmd` は完全build artifact ZIP内で使用します。GitHub Releaseの単独assetとしては配布しません。
- 正式tagは `v0.91.0` を使用します。

## Known limitations

- YMODEMはstop-and-wait protocolのため、921600 bpsでもline rateそのものには到達しません。
- RX DMAは現時点ではthroughput向上よりCPU負荷低減の効果が中心です。
- INTERNAL 1,024×2,047はPSRAM利用時のみです。PSRAMが使えない場合は256×191へfallbackします。
- Direct / prompt入力は191文字です。2,047文字lineはFull-Screen Editorまたはfile経由で扱います。
- AudioCache PSRAM prefetch、CPB Fast Transfer、BLE GATT File Transfer、追加TinyUSB / flush最適化は本リリースには含みません。
- Filesはroot-onlyです。
