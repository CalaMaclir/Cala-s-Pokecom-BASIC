# Version 0.92 Japanese PDF reproduction

The official three-document route is tools/generate_manual_pdfs.py with tools/requirements-manuals.txt (ReportLab4.4.9, japanize-matplotlib1.1.3). tools/build_manual_pdf.py remains the legacy single-volume route for old docs/manual-ja.md; no parallel generator is introduced.

Inputs: docs/install-manual-ja.md, docs/system-manual-ja.md, docs/programming-reference-ja.md.
Outputs: docs/Cala-Pokecom-BASIC-v0.92-{Install-Manual,System-Manual,Programming-Reference}-ja.pdf.
Store all three current PDFs and docs/manuals-manifest.json in the development repository, alongside the Markdown inputs. docs/manual-ja.md and both READMEs link directly to these PDFs. Generated Actions artifacts alone are not a replacement for the repository's manual links. Historical v0.90 PDFs remain available under their versioned filenames.
Manifest: docs/manuals-manifest.json records source/PDF/generator SHA256, version, ReportLab and font.
From the complete development-repository source tree, run python3 -m pip install -r tools/requirements-manuals.txt; python3 tools/generate_manual_pdfs.py; python3 tools/validate_release_docs.py. The build artifact ZIP is a distribution package, not the complete source tree required by validate_release_docs.py.
Embed an IPAex Gothic subset from the pinned japanize-matplotlib package; Courier is used for ASCII code. CID fallback was rejected because Poppler displayed missing Japanese glyphs. No standalone font files are bundled. The manifest records the font SHA256. SOURCE code spaces/indent and display-number examples are preserved. Cover, live TOC bookmarks/page numbers and header/footer identify0.92. invariant Canvas omits changing creation time.

Generate twice in the same environment and compare actual SHA256 to verify same-environment byte reproduction. Different ReportLab/font/Python environments are not claimed bit-identical. Actions manuals/build may regenerate PDFs independently; compare their manifests against final Markdown rather than assuming equality.

The manuals workflow runs for relevant main pushes and pull requests. In its pinned Python3.12/ReportLab/font environment, it regenerates the PDFs and requires the committed PDFs/manifest to remain unchanged. When changing a manual source or generator, regenerate and commit the PDFs and manifest in the same PR. validate_release_docs.py checks current index/README links in addition to versions, limits and hashes. Public-repository synchronization and Release publication remain separate release steps.

Render every PDF page to PNG using Poppler (pdftoppm -png -r 110 input.pdf prefix), review every page for glyphs, overlaps, tables, code, wrapping, page breaks. The private preparation receipt records exact page counts and final hashes after QA. Text extraction alone does not constitute layout verification.
