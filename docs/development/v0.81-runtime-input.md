# Version 0.81 runtime input

Version 0.81 introduces runtime key input without using the REPL line editor.
The Version 0.8 manual and release remain unchanged while this feature is in
development.

Version 0.81 also improves program editing by retaining the successful LOAD or
Save As target as the current filename.

## Program editing and SAVE

`SAVE` without an argument writes the current program back to the filename
established by the most recent successful LOAD or Save As operation.

- `LOAD "GAME.BAS"` followed by `SAVE` updates `GAME.BAS`.
- `SAVE "GAME2.BAS"` performs Save As, makes `GAME2.BAS` current, and allows
  later argument-free `SAVE` commands to update it.
- `NEW` clears the current filename. A following argument-free `SAVE` reports
  `?FILENAME REQUIRED` and cannot overwrite the previously loaded file.
- A failed LOAD or SAVE does not change the current filename or clear the dirty
  flag.
- The normalized ProgramStore filename is the source of truth, so `SAVE "TEST"`
  displays and retains `TEST.BAS`.

Both current-file SAVE and Save As use the existing transactional
`ProgramStore::save()` path. This preserves temporary-file replacement,
storage locking, SD-backed working files, and USB Mass Storage ownership
protection in SD CARD, INTERNAL RAM, and both AUTO backend outcomes.

The Control Center now has `Save Program` and `Save Program As...` immediately
after `Files`. `Save Program` uses the same current-file helper as the BASIC
command. When no current filename exists it opens the Save As filename editor.
Save As asks before replacing an existing file, with `Cancel` selected by
default. A successful save clears the status-line dirty marker.

## Cause of the previous BREAK delay

The VM previously called `platform::break_requested()` only when the low 12
bits of the logical dispatch counter were zero (nominally every 4096
dispatches). Fused instructions can advance that counter by more than one,
and a short `SLEEP`/`GOTO` loop may take a long time to reach the next check.
In addition, `SLEEP n` called `sleep_ms(n)` once, so no BREAK or background
service was possible during the wait.

## Runtime input architecture

REPL input remains in `platform::get_char()`. Runtime code instead uses:

- `poll_runtime_key()` for non-blocking input
- `wait_runtime_key()` for a low-CPU blocking wait
- `RuntimeKeyType::None`, `Key`, and `Break` as distinct internal results

The runtime path does not show or blink a cursor, start the line editor, print
a prompt, or redraw a disabled status area. PicoCalc keyboard reads retain the
existing 200 ms I2C throttle. USB CDC and UART reads are non-blocking; common
ANSI cursor/function-key sequences are decoded by a short state machine rather
than a blocking read. Screenshot, standby, Caps Lock, and modifier events are
consumed as global/state events and are not returned as ordinary BASIC keys.

Normal keys found by periodic BREAK polling are placed in an eight-entry queue
so a later `INKEY` or `PAUSE` can consume them. BREAK is never returned as an
INKEY numeric value.

## BASIC language additions

### PAUSE

`PAUSE` waits until a normal key is pressed. It preserves the displayed
graphics. BREAK aborts the program through the normal `BREAK IN <line>` path.
The wait sleeps for 10 ms between polls, so it is not a busy loop and platform
background service continues to run.

### INKEY

`INKEY` is a zero-argument numeric function. Parentheses are optional.

- no key: `0`
- normal key: the existing PicoCalc/console key code
- BREAK: program interruption

Printable keys use ASCII codes. Existing special-key codes are retained (for
example left/up/down/right are `0xB4`/`0xB5`/`0xB6`/`0xB7`).

## BREAK and SLEEP strategy

The dispatch check is now deadline-based rather than a bit-mask equality test,
so fused operations cannot skip it. The interval is 2048 logical dispatches.
The platform continues to limit physical I2C keyboard reads to once per 200 ms.

`SLEEP` is split into at most 10 ms chunks. Each chunk services the background
callback and checks BREAK. Zero and negative durations preserve their Version
0.8 behavior and return immediately.

## Host verification

The sanitizer runtime test covers:

- PAUSE release by a normal key and abort by BREAK
- no graphics write while PAUSE waits
- INKEY returning 0, ASCII, and an existing cursor-key code
- INKEY aborting rather than returning a BREAK code
- 25 ms, zero, and negative SLEEP behavior
- interruption of a long SLEEP after three 10 ms chunks
- existing tight-loop BREAK, RUN/direct, ProgramStore, and 400-line tests
- current-file SAVE after LOAD, Save As filename replacement, and NEW filename
  clearing
- failed SAVE preserving the current filename and dirty state
- current-file SAVE through SD CARD, INTERNAL RAM, AUTO/SD, and AUTO/RAM
  ProgramStore configurations

For dispatch-overhead selection, the same optimized host runtime workload
(`picocalc_mand.bas` plus `julia_graphics.bas`, 30 repetitions in alternating
runs) was built with the old 4096 interval and the new 2048 interval:

| Setting | Mean elapsed |
| --- | ---: |
| 4096 dispatches | 3.801 s |
| 2048 dispatches | 3.788 s |
| Difference | -0.3% |

This is within host timing noise and below the 2% regression target. The first
512-dispatch candidate was rejected after showing about 11% overhead in the
same environment.

## Real-device checks required

- Measure BREAK latency for `10 GOTO 10`.
- Measure BREAK latency for `10 SLEEP 100:20 GOTO 10`.
- Confirm PAUSE preserves a full-screen graphics image and responds to both a
  normal key and BREAK.
- Confirm INKEY from PicoCalc keyboard, USB CDC, and UART, including arrows.
- Verify Alt+S, standby, Caps Lock, USB CDC/MSC, storage, and network background
  behavior while PAUSE or SLEEP is active.
- Record PicoCalc Mandelbrot and Julia times before merge.
- Load and edit `TEST.BAS`, enter `SAVE`, and confirm both the SD file update
  and removal of the status-line `*`.
- Save As `TEST2.BAS`, edit again, enter `SAVE`, and confirm `TEST2.BAS` is the
  updated target.
- Repeat current-file Save and Save As from the Control Center, including
  Cancel and Overwrite for an existing Save As target.
- Confirm all save paths refuse access while the SD card is owned by USB MSC.
