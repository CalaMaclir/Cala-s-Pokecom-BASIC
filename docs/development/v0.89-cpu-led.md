# Version 0.89 development — CPU, board LED, and Bluetooth Keyboard

## Scope

Version 0.89 adds two user-facing system controls:

- a session-only 200 MHz experimental RP2350 CPU profile;
- Pico 2 W board LED modes OFF, ON, and HEARTBEAT.

It also removes Bluetooth Classic serial transport and focuses Bluetooth on
Classic and BLE HID keyboard input.

## Clock design

Cold boot, reset, watchdog reboot, and BOOTSEL return paths keep the SDK's
150 MHz startup. CPU speed is never written to RMBASIC.CFG; legacy cpu_mhz
values are parsed only to force the safe 150 MHz boot profile.

The existing 75/100/150 MHz profiles continue to divide clk_sys from PLL_SYS.
The first 200 MHz request is different: check_sys_clock_khz validates an exact
SDK-supported PLL configuration and set_sys_clock_khz applies it without any
VREG change. clk_peri is moved briefly to PLL_USB while PLL_SYS is rebuilt,
then sourced from the 200 MHz PLL through RP2350's fractional divider at a
reported 150 MHz. LCD/SD SPI and UART therefore retain their established
peripheral timing. clk_usb remains independent. Keyboard/external I2C and PWM
audio timing are recalculated after every clk_sys change.

The PLL transition is refused while USB MSC owns the SD card or after CYW43
has been initialized. Select 200 MHz before enabling Board LED, Wi-Fi, or
Bluetooth. Once the 200 MHz PLL is active, 150/100/75/200 profile changes only
divide clk_sys and remain available. A power cycle is always the recovery path.

## Board LED

wireless.cpp remains the sole owner of cyw43_arch_init. OFF does not initialize
CYW43. ON and HEARTBEAT lazily initialize the chip without enabling either
radio. HEARTBEAT is a non-blocking 120 ms pulse in a 1000 ms period, driven
from monotonic time by the normal background service.

The selected mode is stored as board_led=off|on|heartbeat. Missing or invalid
values become OFF. STANDBY, BOOTSEL, and reboot force the physical LED off;
wake restores the selected mode. Turning the LED off never deinitializes
CYW43, preserving Wi-Fi and Bluetooth ownership.

## Host coverage

system_controls_test verifies supported CPU profiles, rejection of 175/225/250
MHz, the experimental marker, forced 150 MHz boot behavior, LED setting
parsing, and heartbeat ON/OFF/wrap timing.

## Bluetooth architecture

The Bluetooth manager now owns BTstack/HCI lifecycle and initializes the
Classic HID and BLE HID keyboard modules. `wireless::init()` remains the only
owner of CYW43 chip initialization. Bluetooth power-off first stops scans and
disconnects keyboard links, then powers HCI off.

The former Classic serial service, remote terminal, test terminal, and
Bluetooth file-transfer route were removed. Bluetooth is now focused on
Classic/BLE HID keyboard input because keyboard support is available and the
maintenance cost of the former transport exceeded its practical value. USB,
UART, and Wi-Fi remain the preferred transfer paths.

Stored registry records that are not explicitly tagged as Classic or BLE HID
keyboards are ignored. A Classic link key alone is not enough to make a device
appear in Paired Devices, so legacy computer pairings remain harmless and
invisible until the user chooses Forget All.
