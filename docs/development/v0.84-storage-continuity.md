# Version 0.84 storage continuity

> This document records the Version 0.84 development stage. For final Version
> 0.85 behavior, see [v0.85.md](v0.85.md) and [manual-ja.md](../manual-ja.md).

The SD-backed ProgramStore keeps its transactional `RMBPdddd.BAS` snapshots
and records the last verified editing workspace in `RMBASIC.SES`. The session
contains the active work file, the user filename (empty for UNTITLED), and the
dirty flag. Session metadata is itself replaced with `SafeFileWriter`.

At boot, a session is accepted only when its referenced snapshot can be scanned
and completely verified. An interrupted metadata replacement may recover from
`RMBSES.BAK`. Invalid metadata or work files never block boot; the firmware
starts a clean workspace instead. Cleanup runs only after that recovery decision
and retains the live/session snapshot while removing exact orphan
`RMBPdddd.BAS` files.

`FILES` lists user `.BAS` programs. `DIR` lists visible root files and
sizes, including WAV, BMP, CFG, BAK and SES files, while hiding ProgramStore and
transfer staging files.

A successful Control Center SD remount reloads CFG/BAK settings and reapplies
UI, Program Storage and network settings. A dirty RAM workspace requires an
explicit Keep current program / Restore SD session / Cancel choice. No session,
cleanup or listing operation accesses the card while USB MSC owns it.
