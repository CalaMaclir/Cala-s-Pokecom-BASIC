# Version 0.90 Stage 2 — Full-Screen BASIC Editor

> Hardware gate: PASS. Stage 3 proceeds in
> [`v0.90-stage3-psram.md`](v0.90-stage3-psram.md).

## Stage 3 visual-wrap evolution

Stage 2's logical-line and transactional editing model remains unchanged, but
Stage 3 replaces the horizontal viewport with fixed-column visual wrapping.
A wrapped row is renderer state only: the cursor is still one logical body
offset and ProgramStore still contains one numbered BASIC line. The first
visual row shows the line number; continuation rows use a blank prefix.

Stage 3 navigation is Left/Right by logical character, Up/Down by visual row,
Shift+Up/Down by a body-height visual page, and Home/End by logical-line
start/end. Find positions the viewport on the matching continuation row and
Goto positions the cursor at wrapped subrow zero. See the Stage 3 document for
the model, tests, and hardware gate.

## Architecture

Stage 2 keeps the short-input `LineEditor` unchanged in purpose. It remains the
editor for `BASIC>` commands, filenames, search terms, and other short prompts.

The full-screen source editor is separate:

- `EditorDocument`: hardware-independent source interface.
- `ProgramStoreEditorDocument`: adapter over the active `ProgramStore`.
- `EditorModel`: logical-line cursor, preferred column, viewport, editing,
  commit, Find/Find Next, Goto, Insert Line, and Delete Line.
- `FullScreenEditor`: PicoCalc controller and renderer.

`Repl` creates `FullScreenEditor` with explicit heap lifetime only while the
editor is open. The large working buffer therefore does not enlarge `Repl` and
is never an automatic stack allocation.

## ProgramStore integration and long lines

`ProgramStore` remains the single source of truth. The editor never copies the
whole program. It borrows visible lines for rendering and owns one 2048-byte
working buffer for the selected logical line.

The SD edit transaction now accepts a length-bearing pending edit rather than
copying through the RAM-only `ProgramLine`. This permits exactly 2047 body
characters plus NUL without truncation. A 2048-character body is rejected.

RAM ProgramStore remains limited to 191 body characters. Attempts to exceed
that limit report `LINE TOO LONG FOR RAM PROGRAM STORAGE`; the existing content
is retained.

The working line is committed with `ProgramStore::set_line()` before vertical
or page movement, Find, Find Next, Goto, Insert Line, Delete Line, Save, Save As,
or Exit. A failed commit leaves the cursor, buffer, and dirty state in place.
SD changes continue to use the existing work file, session metadata, safe-file
transaction, hash verification, and recovery policy.

## Viewport and navigation

The editor treats BASIC number and body as one logical source line while
rendering the number in a fixed eight-column prefix. The body uses horizontal
viewport scrolling; no visual wrapping is performed.

- Up/Down: previous/next logical line, preserving the preferred column.
- Left/Right: one character.
- Home/End: body start/end. HOME does not open Control Center in editor context.
- Shift+Up/Down or dedicated Page Up/Down codes: one visible logical page.
- ESC/F10: exit request.

Internal PicoCalc, Classic HID, and BLE HID input all pass through the existing
unified platform key path.

## Commands

- F1 Save
- F2 Find (case-insensitive, current cursor through end of program)
- F3 Find Next
- F4 Goto Line (exact, next larger line, or last line)
- F5 Insert Line (duplicate numbers are rejected explicitly)
- F6 Delete Line (Cancel is the default)
- F7 Save As
- F10 Exit

Enter does not split or renumber lines. New logical lines are created only by
F5, so the editor never performs implicit renumbering.

## Save and exit

Save and Save As reuse `ProgramStore::save()` through the storage adapter.
Save As checks for an existing file and defaults to Cancel before overwrite.

On exit with unsaved changes, the choices are:

- Save
- Keep Unsaved
- Cancel

There is no misleading Discard command. Keep Unsaved returns to `BASIC>` with
the ProgramStore dirty and preserves the existing editing-session recovery
semantics.

## Entry points

- `EDIT` at `BASIC>` opens the current ProgramStore.
- Control Center contains `Editor`.
- Files PROGRAMS mode adds `E EDIT`, which loads the selected BAS file and
  opens it in the editor.

## Memory strategy

- No whole-program SRAM copy.
- One 2048-byte body buffer inside the heap-lived editor model.
- No PSRAM dependency.
- No large automatic stack line buffer.
- Visible non-current lines are borrowed from ProgramStore only while drawn.

The CI memory report records Flash, `.data`, `.bss`, static SRAM, maximum
compiler stack frame, and `sizeof(Repl)` relative to Stage 1.

## Tests

`editor_model_test` covers empty/one/multiple lines, boundaries, preferred
column, insertion/deletion, horizontal and vertical viewport movement, page
clamping, Find/Next, case folding, long-line matches, Goto semantics, backend
limits, dirty state, and injected commit failure.

`program_storage_test` edits an SD line at column 2000, commits all 2047
characters, rejects character 2048 without modifying the source, saves,
reloads, and compares the complete body byte-for-byte. Existing compiler, VM,
LIST, RUN, storage transaction, session recovery, USB ownership, and Stage 1
tests remain enabled.

## Current limitations

- Insert mode only.
- No line split on Enter.
- No automatic renumber.
- No undo/redo, clipboard, syntax highlighting, tabs, or PSRAM cache.
- Find does not wrap at end of program; it reports `NOT FOUND`.
