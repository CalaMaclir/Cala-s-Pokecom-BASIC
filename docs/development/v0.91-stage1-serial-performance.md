# Version 0.91 Stage 1: Serial transfer performance

Status: **PARTIALLY HARDWARE VERIFIED**

## Architecture

Before:

```text
X/YMODEM -> one-byte read -> stdio USB or 1 KiB UART IRQ ring
YMODEM TX -> prefix write + payload write + CRC write
```

After:

```text
X/YMODEM -> read-exact bulk API -> USB CDC short-read loop
                                  -> UART0 4 KiB SRAM ring
                                             |- IRQ (default)
                                             `- RP2350 DMA (optional)
YMODEM TX -> one 133/1029-byte packet write (default)
```

The protocol core remains independent of TinyUSB, UART, and DMA. The wire
format, retry counts, CRC16, duplicate-block handling, batch semantics,
two-EOT flow, and Tera Term one-EOT compatibility are unchanged. USB CDC is
not limited by the UART baud selection.

## Session-only Control Center settings

`Control Center -> Serial Config...`

- YMODEM RX Bulk: ON (default) / OFF
- TX Packet Coalesce: ON (default) / OFF
- Micro-USB CDC Bulk: ON (default) / OFF
- UART Transfer Baud: 115200 (default), 230400, 460800, 921600
- UART RX Mode: IRQ (default) / DMA

The Pico 2 W Micro-USB connector is the native USB CDC route; its transfer
speed is independent of the UART baud setting. The PicoCalc USB-C connector is
the CH340/UART0 route. The PC terminal baud must match the selected UART
transfer baud for USB-C transfers. The selected baud is applied only while a
UART file transfer owns UART0; normal UART stdio returns to
`PICO_DEFAULT_UART_BAUD_RATE` afterward. UART DMA accelerates RX only. A failed
DMA channel claim reports `UART DMA UNAVAILABLE`; it does not silently fall
back to IRQ.

## Hardware checklist

Unchecked items below are **NOT YET HARDWARE VERIFIED**.

### Verified 921600 baud result

Tested with YMODEM over the PicoCalc USB-C (CH340/UART0) route:

| RX mode | Direction | Measured throughput | Result |
| --- | --- | ---: | --- |
| DMA | PC -> PicoCalc | 33 KB/s | PASS |
| DMA setting | PicoCalc -> PC | 62 KB/s | PASS |
| IRQ | PC -> PicoCalc | approximately unchanged | PASS |
| IRQ | PicoCalc -> PC | approximately unchanged | PASS |

The DMA selection applies only to UART receive. Therefore, PicoCalc -> PC uses
the normal UART TX path even while the RX mode setting is DMA.

## Known limitations

- Performance settings reset to their safe defaults at boot.
- DMA is used only for UART0 receive while a file transfer is active.
- Real throughput is intentionally not displayed in the user interface.
- Actual transfer speed and high-baud signal integrity require the hardware
  checks above; CI does not claim hardware performance.
